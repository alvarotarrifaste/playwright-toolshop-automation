# Functional requirements and evidence

This catalogue preserves the Release 1 leadership decisions and records the human-approved post-merge Release 5 Add to Cart refinement. Requirement status and evidence are separate: **existing automation proves what the framework currently validates; it does not automatically establish intended product behavior**. Release 5 covers anonymous and authenticated sessions; non-cart approval statuses remain unchanged.

## Status and evidence model

Requirement status: **Approved**, **Approved / implementation deferred**, **Requires confirmation**, **Proposed**, or **Deferred**. Approval is a leadership decision, not an inference from a passing test. Minor review conditions are recorded separately.

Evidence types: **Official/project-owned documentation**, **Application observation**, **Existing automation behavior**, **Existing repository evidence**, or **Proposed / requires confirmation**. Multiple evidence types may support one record. A passing execution confirms the assertions on that run, not the entire requirement or official intent.

**O13 — Controlled runtime observation:** own third seeded enabled customer initially logged in (200), three invalid attempts returned 401, subsequent wrong/correct attempts returned 423, and the positive customer still returned 200. **REQ-API-AUTH-002 — Approved, explicit post-merge human leadership decision (L13).** Explicit authenticated GET /users/logout invalidates that access token: a token which can read /users/me before logout receives HTTP 401 with the protected-route Unauthorized error afterward.
