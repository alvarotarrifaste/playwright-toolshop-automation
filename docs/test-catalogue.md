# Existing automation and traceability

Nineteen scenarios are implemented: sixteen UI and three API. Release 13 adds account locking and explicit API logout invalidation, and strengthens the existing UI logout case without duplicating it. Release 11 adds one authenticated cash-on-delivery purchase under Approved REQ-PURCHASE-001 (L11 human review). Release 10 adds two checkout identity/billing-progression UI cases under Approved REQ-CHECKOUT-001 (L10 human review), explicitly preserving the guest alternative. Release 7 adds category selection/clearing and search resetting category state; REQ-CATALOG-005 is Approved by explicit human leadership decision during Release 12 (L12-CATALOG), while existing REQ-CATALOG-002 remains Requires confirmation. Release 6 adds two independent anonymous cart-maintenance scenarios; their requirements are approved by the post-merge human leadership decision (L6). The original seven names/assertions and T-CART-001 anonymous implementation are preserved. Release 5 PR #8 introduced T-CART-001; its human-approved post-merge change request adds T-CART-002 authenticated coverage. IDs are documentation identifiers. Release 2 supplies a controlled target, reset before execution and separate authentication customers. Requirement status comes from [the requirements catalogue](requirements.md), independently of the original and follow-up [Release 5 execution evidence](release-05-summary.md).

Phase 1 priority proposals do not establish approved priority labels. Native R12 layer/domain/regression tags and five selected smoke cases remain the operational convention. Full controlled execution discovers all 19 scenarios (16 UI + 3 API); optional subsets use the same runner.
